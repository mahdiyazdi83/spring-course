# Real-session processing checklist

- Confirm authorization, weekday, number and file-to-session mapping; request only missing essentials.
- Read the entry point, applicable workflow, content rules/model, affected page and directly related concepts.
- Inventory actual sources; never invent absent recordings, timestamps, speakers or repository revisions.
- Keep Tuesday follow-ups in their original session; keep Thursday events independent.
- Preserve stable route, content ID, block IDs and heading anchors when updating material.
- Separate learning order from the actual recording timeline; each timestamp belongs to its own recording.
- Attribute teacher/Heydari material independently; label generated explanations and code as GPT.
- Use Teacher Code only with a verified historical repository pin and matching path/snippet.
- Before linking real content to a demo concept, replace its simulated teaching/provenance with verified documentation,
  or create a separate valid real concept. Do not merely flip `demo: false` while fictional material remains.
  Preserve unrelated demos as explicitly labeled examples; never present simulated occurrences as course history.
- Record missing evidence and an honest incomplete status; no empty source blocks to activate filter options.
- Update only affected concept edges, prerequisites, status, dates and meaningful changelog entries.
- Keep referenced targets published; native `draft: true` pages cannot be targets of published content.
- Run `npm run check`; inspect the built page, all available source combinations, context/corrections and deep links.
- Search a Persian topic and an English technical term in build + preview; check mobile and code/table scrolling.
- Leave one concise processing log with actual coverage and remaining gaps. Do not reprocess the entire course.
