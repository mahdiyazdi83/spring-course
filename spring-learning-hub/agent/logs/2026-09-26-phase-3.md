# Phase 3 — documentation components and source behavior

Completed only the authorized third phase. Existing design, routes and Starlight shell
are retained. No files in the real course source folders were read or processed.

- Added SourceBlock, GptNote, TechnicalCorrection, CodeExample, SourceFilter,
  PrerequisiteList, SessionMeta, DocumentStatus, ChangeLog and ConceptAppearances.
  SessionTimeline now renders validated page metadata directly, including source/recording
  captions, timestamps, approximate timing and topic-only entries.
- Implemented all source combinations with direct context summaries and necessary
  corrections. Empty groups and both native TOCs stay synchronized; hidden anchor
  targets restore the full document. Controls progressively enhance server-rendered text.
- Added static MDX provenance validation using the official parser, including direct
  import aliases, recording/duration checks, context/correction references, and code
  attribution requirements. Added optional prior-session prerequisites with graph checks.
- Updated the Tuesday demo with explicitly simulated human roles and a local generated
  snapshot; Thursday stays separate without the filter. Concept occurrences now derive
  from session edges. All seven requested code languages render through Expressive Code.
- Added ADR 0005 and COMPONENTS.md; updated common, Tuesday, Heydari, Thursday and concept
  workflows, content/design/architecture documentation and README.

## Verification

`npm run check` passed: format, lint, Astro/TypeScript (34 files, zero errors/warnings),
17 tests, seven-document metadata/graph/MDX validation and build (eight pages with 404).
All eight source combinations are covered by pure-model tests and exercised in the
built browser preview. Negative tests cover absent Heydari/GPT content, missing times,
undeclared sources, wrong recordings, excessive timestamps, dangling/cyclic contexts,
nested attribution, expression/spread props, aliases, unpinned Teacher Code and demo
locators in real documents. Existing content-model checks remain passing.

Browser QA: 1440px desktop, 768px tablet, 390px and 320px mobile; light/dark themes,
Persian prose, annotations, long LTR code and independently scrollable regions. Checked
pages had no horizontal document overflow. Verified keyboard Space toggling and visible
focus, live status/empty state, native copy feedback, source summaries, correction retention,
desktop/mobile TOC synchronization and anchor reveal. Thursday has ordered untimed items
and linked concept/prior-session prerequisites. Java Demo.java compiled and ran locally;
the other short snippets are illustrative fragments, not a complete Spring application.

The three pre-existing non-blocking MDX directive, default-404 lookup and absent deployment
hostname warnings remain documented and unsuppressed. This is targeted browser and unit
verification, not a full multi-browser/screen-reader audit.

Official APIs consulted: [Starlight Code](https://starlight.astro.build/components/code/),
[Expressive Code](https://expressive-code.com/key-features/code-component/),
[MDX parser](https://mdxjs.com/packages/mdx/). The illustrative scope correction was
checked against [Spring Bean Scopes](https://docs.spring.io/spring-framework/reference/core/beans/factory-scopes.html).

Pagefind search and Phase 4 are not started. Real attribution still needs human/editorial
source verification; structural checks cannot prove a speaker said a claim or guarantee
a supplied snippet matches the declared repository pin.
