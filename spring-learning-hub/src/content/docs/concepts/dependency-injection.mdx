این توضیح کوتاه و کد همراه آن توسط GPT برای نمایش قالب مرجع مفاهیم نوشته شده‌اند؛ هنوز جمع‌بندی محتوای واقعی دوره نیستند.

## معرفی [#overview]

<SourceBlock id="concept-overview" source="gpt">

تزریق وابستگی یا `Dependency Injection` یعنی شیء، همکار موردنیازش را از بیرون دریافت کند. به جای اینکه هر کلاس مسئول ساخت همهٔ اشیای موردنیاز خودش باشد، می‌توان مسئولیت ساختن و متصل‌کردن آن‌ها را در جای دیگری قرار داد.

</SourceBlock>

## چرا به آن نیاز داریم؟ [#why]

<SourceBlock id="concept-purpose" source="gpt">

وقتی یک سرویس فقط به قرارداد موردنیازش وابسته باشد، می‌توان در شرایط مختلف همکار متفاوتی به آن داد. برای نمونه، در زمان آزمایش می‌توان از یک پیاده‌سازی ساده استفاده کرد که پیام را واقعاً ارسال نمی‌کند. در نتیجه، بررسی منطق سرویس از بررسی سامانهٔ ارسال پیام جدا می‌شود.

</SourceBlock>

## یک مثال با Java [#java-example]

<SourceBlock id="concept-example" source="gpt">

در این مثال، وابستگی با سازنده دریافت می‌شود. `Sender` فقط یک interface کوچک است و نمونه بدون نیاز به پیکربندی Spring، ایده را نشان می‌دهد.

```java title="Notifier.java · GPT Example"
interface Sender {
    void send(String message);
}

final class Notifier {
    private final Sender sender;

    Notifier(Sender sender) {
        this.sender = sender;
    }

    void notify(String message) {
        sender.send(message);
    }
}
```

</SourceBlock>

## نکته‌های رایج [#pitfalls]

<SourceBlock id="concept-pitfalls" source="gpt">

<ReadingNote title="مفهوم را به annotation محدود نکنید">
  تزریق وابستگی یک روش طراحی است. ابتدا می‌توان آن را در Java معمولی فهمید و بعد نقش Spring در ساخت
  و اتصال اشیا را بررسی کرد.
</ReadingNote>

ساختن یک interface به‌تنهایی به معنای تزریق وابستگی نیست. پرسش اصلی این است که شیء موردنیاز کجا ساخته می‌شود و چگونه به کلاس مصرف‌کننده می‌رسد.

</SourceBlock>
